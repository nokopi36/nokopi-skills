# 仕様抽出プロンプト

> Claude Code にそのまま貼って使う。**このフェーズではコードを書かせない。**

---

`refs/{{SOURCE_REF}}/` にある {{MOD_NAME}}（{{SOURCE_MC}}）のソースを全部読み、
{{LOADER}} {{TARGET_MC}} で再実装するための仕様書を `docs/SPEC.md` に書いてください。
`docs/SPEC.md` 以外のファイルは作成・変更しないでください。

## 読み方
- `refs/{{SOURCE_REF}}/{{SOURCE_JAVA_PATH}}` の全ソースファイル
- `refs/{{SOURCE_REF}}/{{SOURCE_RESOURCES_PATH}}`（言語ファイル、テクスチャ一覧、メタデータ）
<!-- アドオンの場合のみ -->
- 元 MOD（{{BASE_MOD_NAME}}）の何を前提にしているか分からないときは `refs/{{BASE_MOD_REF}}/` の対応クラスを探す。
  旧バージョンの元 MOD の挙動を推測する場合は **[推測]** と明記

## SPEC.md に含める内容

### 1. 概要
目的、追加要素の全体像、依存関係

### 2. 追加コンテンツ一覧（表）
内部名 / 表示名（英・日）/ 種類 / 元ソースのファイル名

### 3. 機能ごとの詳細仕様
各要素について**数値つきで**。数値は元コードの定数・式から引用し、ファイル名と行番号を添える。
- 挙動（何をするか、発動条件、ティック処理）
- 数値（生成量・容量・倍率・クールダウン・範囲など）
- 保持するデータ（新バージョンでどこに置くべきかの提案つき）
- GUI のスロット構成・ボタン・表示値
- クライアント⇔サーバー間の通信
- キー操作
- config 項目とデフォルト値

最低限、次は必ず詳細に書くこと:
{{KEY_FEATURES}}

### 4. レシピ一覧
全レシピを材料配置つきで。特殊レシピは判定ロジックを文章で。

### 5. 他 MOD／バニラへの改変
ASM・Mixin・リフレクション等で既存クラスを書き換えている箇所について:
- 対象クラス・メソッド・注入位置
- 改変前後でプレイヤーから見た挙動の違い
- 新バージョンでの代替案を優先度順に（①API・イベント ②継承・差し替え ③Mixin。注入先候補を `refs/` のクラス名で）
無効化されている改変も「無効」と明記。該当がなければ「なし」と書く。

### 6. 移植上の論点
- 新バージョンの{{BASE_MOD_OR_VANILLA}}にすでに同等機能があり不要になりそうなもの
- 再現が難しい・意味が変わるもの
- 人間に決めてほしいこと（箇条書き）
{{SCOPE_EXCLUSION}}

### 7. 実装順の提案
依存関係を考慮した順番と、各ステップの完了条件。

## 最後に
- 読んだファイルの一覧と、理解できなかった箇所を末尾に列挙
- 確信が持てない数値・挙動には **[要確認]** を付ける
